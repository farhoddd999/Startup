# Hearth

**Be the one who reads the bedtime story.**

Hearth is a private reading coach for parents who struggle to read. A parent practises tonight's picture book alone for about five minutes, with a coach that listens and helps the moment they pause, then reads it aloud to their child. Every night, two people get better at reading.

- 28% of U.S. adults score at or below the lowest literacy level measured (PIAAC 2023), and 77% of adults at the lowest levels are parents.
- Every reading app listens to the child. Hearth listens to the parent, at the moment that matters most to them: their own child at bedtime.
- Families never pay. Head Start programs, libraries, adult education, pediatric networks and health plans do.

## Try it

```bash
cd product
npm install
npm test          # engine, tracker, learner and story-validation tests
npm start         # http://localhost:8787/   (website; the app is at /app/ → /product/)
```

On the first screen choose **"Explore with a demo family"** (or open `/product/?demo`). Tap **Practise first**: the demo reader reads aloud in text, pauses on a word, and you can watch the hints arrive (chunks, then sounds, then the word). Then try **Read with Mateo** for story time, and **Your sky** for progress. On a desktop, the side panel switches between your voice, the demo reader and tap mode.

To let Hearth write new stories live, set `ANTHROPIC_API_KEY` before `npm start`. Every generated story is checked word by word and revised until every word is readable for that parent.

## The website

Eleven pages plus a 404, all static, with the product's real engine and stories running in the browser:

- **How it works** with the live app embedded, **For families** (English and Spanish, read-aloud, a note-to-your-program generator), **For programs** (use cases, dashboard, pricing calculator, pilot plan), **The science** (40-step sequence explorer), **Decodability checker** (paste any text, see which words a reader can read), **Story library** (all 14 stories, personalised, page by page), **Research and sources**, **About**, **Privacy**, **Start a pilot** (request form).
- Short addresses: `/app`, `/demo`, `/studio`, `/dashboard`, `/test`.

Edit pages in `site/pages/`, then rebuild:

```bash
node site/build.mjs            # pages, _redirects, _headers, robots.txt, favicon
node site/build.mjs --images   # also the social card and touch icon (uses Playwright)
```

Set `HEARTH_CONTACT=you@yourdomain` (pilot form, footer email, and where tester feedback is addressed) and `HEARTH_SITE_URL=https://yourdomain` (canonical links and sitemap) before building. The build also stamps the app with a build number (a hash of the app's files) and regenerates the service worker's offline file list.

## Testing with real people

Send testers to **`/test`** (the tester guide at `/testers/`, unlisted and not indexed). It has a QR code that opens the app, install steps for Android and iPhone, a 20-minute "what to try" checklist, privacy in plain words, known limits, and a printable 30-minute session guide for program staff, with a consent script. Parent sections are in English and Spanish.

In the app, **Settings → Send feedback** (and **Tell us how it went** after story time) lets a tester tap a face, pick quick notes, record a voice message, or write. They see exactly what will be sent, then share it through their phone's share sheet, email, or copy. Nothing is sent automatically, and the child's name is never included; a practice summary (counts only) is added only if the tester switches it on. Every message carries the build number and device type, so reports can be matched to a build.

Before testing with families who find reading hard, put a consent process in place (see the session guide), and know that in this prototype the browser's speech recognition may send audio to the browser maker. The app says so on the microphone screen before the microphone is allowed.

## Deploy (Cloudflare or Vercel)

The site is plain static files served from the repository root; no build step runs on the host. `site/build.mjs` writes the same redirects (short addresses, private paths) and headers (security, caching) for both hosts, so they behave the same.

- **Cloudflare Workers** (Workers Builds, `npx wrangler deploy`): uses `wrangler.jsonc`. Its `name` must match the Worker's name in the Cloudflare dashboard. `.assetsignore` keeps `docs/`, `pitch/`, `site/` and the server code out of the upload (92 public files).
- **Cloudflare Pages**: no build command; build output directory `/`. Reads `_redirects` and `_headers`.
- **Vercel**: import the GitHub repository at vercel.com/new, keep the framework preset **Other**, leave the build command empty and the root directory as is, then deploy. Uses `vercel.json` (redirects run before files are served, so private paths are never reachable) and `.vercelignore` for CLI uploads. Every push to `main` redeploys.

Hosting on the free tiers: Cloudflare doesn't charge for static-file traffic. Vercel's Hobby plan is for non-commercial use, so a company site belongs on Vercel Pro. A home-page visit is about 470 KB and 11 requests; opening the app for the first time is about 390 KB and 35 requests.

Live story writing needs the Node server and an API key, so on static hosting the app and Studio use the story library; everything else works offline-first in the browser.

## How it works

1. **Phonics engine** (`product/engine/`): maps every word to its sounds using the CMU Pronouncing Dictionary and a 40-step sequence of 120 letter-sound patterns, so Hearth knows exactly which words a parent can read.
2. **Stories**: written for one step and validated in CI; new ones are written by Claude for one family and checked by the engine.
3. **Reading coach**: follows the parent's voice word by word; gives the smallest hint that helps.
4. **Learner model**: Bayesian knowledge tracing per sound; a sound counts as learned only after good reading on two different days.

Details: [`docs/technical-architecture.md`](docs/technical-architecture.md), [`docs/pedagogy.md`](docs/pedagogy.md).
